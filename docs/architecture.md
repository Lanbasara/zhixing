# 知行的内容架构

知行是给 agent 使用的工程能力包，没有自己的运行服务、任务数据库或工作流引擎。
宿主负责发现与调用技能，项目保存事实与进度，agent 根据当前目标组织工作。

## 内容归属

| 位置 | 维护的内容 |
| --- | --- |
| [PHILOSOPHY.md](../PHILOSOPHY.md)、`principles/` | 跨任务的判断依据，作者与使用者共享 |
| `skills/zhixing-*/SKILL.md` | 各项能力的专业责任、完成含义和条件引用 |
| `references/` | 上下文、项目知识、验证与 HTML 的共享协作约定 |
| `.claude-plugin/`、`.codex-plugin/`、`agents/openai.yaml` | 宿主识别包与技能、控制调用方式所需的元数据 |
| `scripts/` | 维护时可确定检查的包契约 |
| [evaluations/](../evaluations/README.md) | 行为检验的方法；一次实验的输入、结果与产物由证据环境保存 |

能力只在相关问题出现时引用原则或共享约定。将详细内容移到另一个文件，却要求
每次全部阅读，并没有减少上下文负担。新增共享文件的理由应是独立维护价值或
实际复用，而非追求目录对称。

## 调用边界

[能力目录](../README.md#能力与调用) 是人的导航。六个人工入口在两个宿主中都关闭
自动调用；其他能力可按任务组合。任何能力都不通过引用自行启动人工入口。
实现者在已有授权中规划、研究或调试，是完成当前职责，不是另开人工工作流。

两份插件清单指向同一个 `skills/`，共享材料保留在包根目录。两种宿主使用同样的
技能名字，宿主命名空间与呈现方式可能不同。元数据处理调用入口，正文解释职责，
二者不能保证宿主之外的工具权限或外部副作用已经获得授权。

不依靠隐藏的会话状态编排后继技能。长任务在项目认可的规格、计划或工作记录里
保存足够接续的信息；新上下文结合当前请求和实际状态恢复。小任务可以只使用
对话与现有材料，不建立额外的计划或状态系统。

## 质量边界

静态检查能证明资源存在、引用可达和显式策略一致，无法证明技能的判断质量。
行为检验让独立 agent 完成实际任务，再根据成果、轨迹和额外负担判断指导是否有用。
原始缺陷、不同条件下的合理任务与真实宿主加载分别回答不同问题，不能互相替代。

插件不内置具体业务、编程语言、实例配置或项目专用运行方式。这些知识在使用方
项目维护；通用原则与工程能力的演进应有跨场景理由。
