# 持续实现到交付

这是人工入口，由用户主动发起；其他技能不自行启动它。入口约束不限制普通编码请求，也不使已有任务授权失效。本次目标明确后，持续推进到完成或出现真实需要人的阻塞，不逐步等待“继续”。

按本次改动的实际影响读取上下文，适用时依据 [上下文约定](../../references/context.md) 接续已有工作。找到并采用相关决定、项目约定与可复用能力；规格和计划不替代这些依据。已有目标、约束和退出条件直接复用，无关材料不必补齐。必要的内部规划、事实调查和计划调整属于本次实现，无需转入人工 plan、align 或 specify 流程。

修改已有界面时，沿项目入口查明适用的设计约定与可复用实现。依据可以来自现有页面、代码、文档或可运行示例，按本次影响选取。复用基础控件不自动证明布局、信息层级与交互符合设计；按变化选择可复跑的验证方式，在实际使用场景中检验。需要偏离已约定设计时说明原因与影响，按其授权边界处理。

选择能尽早取得有效反馈的实现顺序。允许边实现边校正方法；新的事实若只改变技术路径，由 agent 调整并说明，若会改变用户目标或实质承诺，则把需要人的取舍说清楚，同时推进不依赖该决定的工作。

独立工作、委派子任务或并行多个 agent 均可，依据复杂度、可分离性和宿主授权选择。委派应明确交付边界与接口；主责 agent 仍负责冲突处理、整体集成和最终行为，不能把各自完成等同于系统完成。

围绕 [共用验证约定](../../references/verification.md) 取得与变化相称的证据，必要时使用 [验证能力](../verify/SKILL.md)；审查实际差异和受影响路径，复杂或高风险问题可使用 [审查能力](../review/SKILL.md)。测试通过不自动证明用户路径成立，评审意见也不替代复核。发现真实问题就修复并验证受影响部分，避免无依据地重复全量检查。

遇到失败，缩小问题并查清原因，必要时使用 [调试能力](../debug/SKILL.md)。重复尝试没有新证据时换策略、工具或问题分解；把客观环境限制与尚未解决的技术问题区分开。只有缺少必要的人类决定、权限或外部条件而无法继续有效工作时，才以阻塞结束，并说明已经完成什么、缺什么及恢复条件。

按 [项目知识约定](../../references/project-knowledge.md) 修正失真的知识和任务状态，保存本次新形成的重要决定与理由。完成意味着结果满足本次目标及适用的项目约束，已经实现、集成并得到足够验证，遗留问题与未验证范围已明示；交付说明结果、证据和实际限制。提交、合并、发布等动作依用户授权与项目约定执行，不能从“实现完成”推导额外授权。
