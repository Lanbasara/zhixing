# 用原型回答设计问题

明确原型要帮助理解或选择什么，复用已经提供的背景。围绕关键不确定性选择
最低成本的可观察呈现：交互、状态模拟或候选比较均可，不要求每次生成多套
方案，也不因原型任务启动完整项目规划。

使用 HTML 表达用户能够体验的关键路径。已有项目环境适合时沿用它；独立
探索默认交付可携带的页面。遵循[HTML 成果约定](../../references/html.md)，
控制实现范围，使原型足以检验问题，不提前建设生产系统。

模拟数据、假设和未连接能力应清楚。原型的价值是学习，不能以演示成功证明
持久化、性能或真实集成成立。若需要一条会进入最终系统的真实路径，应按
[反馈与真实路径](../../principles/feedback.md)判断是否转为曳光弹实现，并
尊重当前任务边界。

实际打开并操作关键路径，观察原型是否能暴露预期的选择和问题。交付 HTML、
得到的认识与仍未回答的事项；用户体验本身是待取得的证据时，保留这个判断。
只把已确认结论带回正式设计，原型代码是否保留依其实际价值决定。
