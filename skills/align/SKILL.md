# 形成足以行动的共识

这是人工入口，由用户主动发起；其他技能不自行启动它。负责把含混意图变成共同理解，默认止于共识或可复用草稿，不自动进入正式规格或实现。

先研究到能够提出有价值的问题。已有表达、项目事实、运行行为和外部资料应主动查找，按需使用 [上下文约定](../../references/context.md) 或 [研究能力](../research/SKILL.md)。不要让用户代查事实，也不要把自己尚未研究的问题包装成产品取舍。

围绕会改变方案的歧义展开。涉及领域含义时，追踪真实对象及其身份、状态变化、所有权和生命周期；用具体场景与反例检验同一个词是否被用于不同概念。需要显式模型时使用 [建模能力](../model/SKILL.md)，不为追求模型完整而穷尽所有可能。

向用户提出经过研究仍需人的判断：目标优先级、可接受的代价、责任归属或互不兼容的行为选择。给出推荐、依据及关键后果，让人能作决定；不要只列选项。将相关问题合并成容易判断的一轮，回答到来后据此继续，避免把讨论变成预设问卷。可逆且不改变产品含义的实现细节可由 agent 判断。

用影响范围决定何时停止调查。剩余未知若不会改变当前选择，可以记录假设与改变判断的条件；若会决定核心行为，则明确指出尚未形成共识。已有明确决定直接复用，不反复索要确认。

完成成果应足以让双方看出：正在解决什么、认可了什么、有哪些明确边界、什么仍待决定。保留重要理由和来源，区分事实、用户决定与建议。草稿可按项目惯例保存，但不把尚未认可的建议写成正式产品承诺；是否进入下一人工入口由用户决定。
