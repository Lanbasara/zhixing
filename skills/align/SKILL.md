# 形成足以行动的共识

这是人工入口，由用户主动发起；其他技能不自行启动它。负责把含混意图变成共同理解，默认止于共识或可复用草稿，不自动进入正式规格或实现。

先研究到能够提出有价值的问题。已有表达、项目事实、运行行为和外部资料应主动查找，按需使用 [上下文约定](../../references/context.md) 或 [研究能力](../research/SKILL.md)。不要让用户代查事实，也不要把自己尚未研究的问题包装成产品取舍。

从用户想完成的事出发，主动找出还没说清、却会改变方案的决定。用具体场景与反例比较合理解释，检验不同答案会改变哪些行为、边界或承诺。涉及领域含义时，追踪对象的身份、状态变化、所有权和生命周期，必要时使用 [建模能力](../model/SKILL.md)。

追查足以改变选择或推翻推荐的事实。对研究后仍需人判断的取舍，给出具体情境、推荐、依据和关键后果。同一轮可以提出几个能独立作答的问题，让用户逐项判断。若一个问题取决于另一个尚未明确的答案，等前提明确后再问。可逆且不改变产品含义的实现细节可由 agent 判断。

收到回答后，更新对目标和边界的理解，检查哪些建议需要调整、哪些后续问题现在才值得问。对仍会改变核心行为的取舍继续讨论，暂时无法决定的明确保留为未决。已有明确决定直接复用，影响较小的未知可记录为带条件的假设。

收束时写清正在解决的问题、已达成的共识、明确的边界和仍待决定的事项。核对各项关键取舍是否已有依据，避免把对整体方向的认可当成逐项决定。保留重要理由和来源，区分事实、用户决定与建议。草稿可按项目惯例保存，是否进入下一人工入口由用户决定。
