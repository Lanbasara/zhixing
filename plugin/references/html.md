# HTML 作为可阅读、可操作的成果

用于原型、解释与报告。先确定读者要理解或操作什么，再选择结构和交互。
图表、动画、筛选或模拟应服务具体问题；文字已经清楚时，不必把它包装成交互。

独立交付默认使用便于携带的 HTML，主要内容无需外部服务即可阅读。已有项目
或用户指定环境时沿用其约定。需要外部资源、库或在线能力时说明依赖，不把
联网作为静态内容可读的隐含前提。

采用语义化 HTML、清晰层级、可读对比和适合不同窗口宽度的排版。交互有可见
标签，键盘可操作，动态变化能被理解。内容较多时提供有效导航；不套用固定
栏目、卡片数量、配色或字体来替代信息组织。

区分事实、模拟与待验证假设。来源就近可追查；输入和数据的变化不应悄悄
改变结论的含义。原型中的演示状态不能被报告为真实系统行为。

交付前在可用浏览器中打开成果，检查关键阅读路径与实际交互，修正遮挡、
溢出、失效按钮和运行错误。没有可用的渲染环境时，完成仍可做的检查并
说明缺少视觉核对，不能把源码检查说成已实际体验。

保留原本论证的条件与强度。表达中发现实质性知识缺口时，说明影响并按任务
需要补查，不自行重新定义整项研究。成果按用户指定位置或项目惯例保存；
需要成为正式约定的内容回到相应项目文档。
