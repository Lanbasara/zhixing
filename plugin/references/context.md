# 按问题获取上下文

用于背景不足、跨会话接续或委派工作时。已有信息足以承担当前职责，就直接
开展工作；本约定不要求每次调用技能都恢复整个项目。

当前目标决定阅读范围。独立研究可以从问题和资料开始，解释既有方案可以
从方案开始。进入具体项目时遵循适用的项目规则，沿相关文档和代码取得必要
事实，不因存在历史、spec 或计划就全部阅读。已经掌握且仍适用的内容直接复用。

接续工作时，找到目标、已确认的决定、当前产物、有效证据和剩余问题。
计划和检查点帮助定位，但其描述需要能对应实际代码及环境；发生相关变化后，
重新判断哪些结论仍成立，不从头重做，也不把旧自述当作当前证明。

留下检查点，是为了让下一位执行者继续判断。保存容易丢失的理由、重要发现、
未完成部分和可行的下一步；能从现有材料取得的事实用链接指向。优先更新原有
计划或任务记录，避免另维护一套相互竞争的进度。

会话切换取决于下一段工作的需要。细微理由仍重要时继续当前会话，独立且
边界清楚的工作可以委派，已有成果能够独立理解时适合交接。不给不同宿主、
模型和任务规定统一的长度阈值。

委派提供足以独立工作的目标、范围、必要材料和验收依据，不假定执行者能看见
其他会话。具体工具、隔离方式和并发度依宿主能力及任务选择；上下文分离不
等于文件、数据或运行实例已经隔离。

需要判断知识归属或恢复粒度时，参阅[知识与局部理解](../principles/knowledge.md)。
