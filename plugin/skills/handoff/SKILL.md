# 让工作能够接续

负责让缺少当前对话的执行者，以合理的阅读和恢复成本继续工作。交接应让
接手者理解目标与边界、实际停在哪里，以及哪些未知会影响下一步。内容与
详略随接续工作的需要决定，不以复述完整对话为目标。

围绕接手者可能作出的决定取舍信息：不知道这件事会怎样影响行动，能否
从现有成果中可靠恢复？优先保留会改变方向且难以重新获得的内容，例如
用户的重要纠正、未落入成果的取舍理由、关键发现和未完成状态。已有成果
能够说明的内容就近引用；容易重新查明的细节与不影响接续的探索可以省略。
下一步尚不明确时，保留当前目标与主要未决问题，不替用户选定后续方向。

对接手者将依赖的重要判断，保留足以理解其依据和适用边界的说明。事实、
用户决定、推断与建议应当可辨；摘要不能把尚未验证变成已确认，也不能把
特定条件下的失败写成普遍不可行。旧认识容易被再次采用时，指出修正及其
理由。无需重放逐步思考，只留下会影响继续判断的关系。

正文应足以开始工作。行动前必须知道的约束直接可见，只有特定问题需要
的细节通过引用展开。引用说明材料能帮助判断什么、何时值得打开，避免
要求接手者先读完全部材料。关键依据应能定位；来源不可访问时，把无法
恢复且会影响接续的内容直接留下，并说明缺口。

按实际需要提供可行的下一步，以及它要解决的未知；建议不替代接手者根据
新事实作判断。没有解决的分歧和重要异常可以保留简短线索，不必为了形成
顺畅叙述而强行收敛。只依据当前可见材料交接，不把未见到的信息写成不存在。

沿用已有任务记录和成果位置，避免另建一套需要持续同步的进度。独立交接
文档没有合适归属时，可保存到系统临时目录，并明确给出读取入口；不假定
接手者能访问当前会话或本机路径。排除凭据和无关敏感信息。交接本身不把
建议升级为项目决定，也不扩大后续工作的授权。

完成前，从接手者的处境检查：能否知道要继续什么、哪些判断仍有条件、
下一步如何推进，以及遇到疑问去哪里查。删去不服务于这些判断的内容；
不能为缩短篇幅而把必要理解转移成大量跳转。接续时的恢复与核对参照
[上下文约定](../../references/context.md)，不要求重建整个项目背景。
