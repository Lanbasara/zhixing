# 演进工作方法

这是人工入口，只在用户主动要求改进工作法时使用；其他技能不因发现失误自动启动它。负责改进产生行为的机制，不把一次任务复盘自动变成全局规则。

从实际经过、输入、执行结果和已有约定中定位问题。区分职责或完成标准不清、上下文缺失、规则冲突、工具缺陷、执行失误以及评价本身偏离目标。必要时使用 [研究能力](../research/SKILL.md) 或 [调试能力](../debug/SKILL.md) 取得证据；不能仅凭最后一个可见错误选定责任层。

判断修复应落在哪里时，参照 [变化与责任层](../../principles/change.md)。项目事实、实例问题和个人偏好留在相应环境；只有跨任务成立的判断才考虑进入通用技能或原则。类似措辞的失误未必同源，同一个根因也可能有不同表现。明确改动适用的条件，以及在哪些合理场景不应生效。

选择能真正消除原因的最小改动。优先改善结构、工具和信息可发现性，或澄清、合并、删除已有指令；确实需要改变可复用规则时，按 [技能设计](../../principles/skill-design.md) 判断新增指导的价值与过拟合风险。

把原问题作为检验材料，同时挑选条件不同但合理的任务，观察改动是否解决根因、增加无关工作或排斥有效路径。评估实际行为与结果，不以命中了特定句子证明质量；有必要时使用独立评估，评估者应获得完成任务需要的材料，而非预设答案。个案过程和试验产物保留在适当证据位置，不进入通用规则正文。

完成时，说明根因判断、修改的责任层、为何能迁移及实际检验范围。保留证据尚不足的结论；无法证明值得加规则时，可以交付有依据的不改或删简建议。对工作法的修改不附带自动安装、全局配置变更或发布。
