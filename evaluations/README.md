# 行为检验

检验的对象是指导对真实工作的影响。执行正文通过工程任务检验；哲学或写作
原则通过技能维护任务检验，观察执行者能否找到正确责任层、写出有效指导，
并保留其他合理路径。结构检查只能证明它实际检查的包契约。

在观察输出之前确定本次要检查的行为和判断依据。向独立执行者提供自然的
用户请求、相应指导及完成工作需要的原始材料，不提供预期答案、推测根因、
建议补丁或比较结论。判断者可以掌握评价依据，执行者应自行完成工作。

观察实际成果是否完成目标、依据是否可靠，以及指导有没有引入无关工作、过早
停顿或遗漏责任。允许不同实现路径；不以固定措辞、标题或步骤判断成功。

需要判断新增指导的贡献时，固定原版与修改版，在相同模型、工具和输入条件下
分别使用新上下文；必要时加入不提供该指导的基线。记录每次运行，避免根据
输出补改题目、反复重试后只保留最好结果，或把同一会话里的后续任务当作独立
样本。小规模对照可以发现具体差异，不能证明跨任务或跨模型的普遍优势。

有价值的情境包括：材料已经充分的解释任务；没有 spec 的局部修复；从已有成果
接续的实现；需要人选择的实质分歧；验证驱动与产品行为不一致；或跨任务迁移
一条新原则。根据改动选择有区分力的任务，不把这些情境变成每次必跑的全集。

核对实际产物与执行证据，再评价完成情况。测试或验证入口应能识别目标失败，
适用时用已知故障或隔离副本中的代表性破坏检验；通过结果和执行者自述都不能
单独证明这种能力。没有改善、出现额外负担和未能区分的结果同样保留，并据此
修订、撤回或限制指导。

在隔离位置保存请求、输入、所测技能版本、执行环境、结果与必要证据；记录创建
了什么资源及其清理情况。涉及真实系统时遵守相应授权。个案内容不进入通用技能，
也不为通过一个案例而添加只能解释该案例的规则。

独立执行通常通过显式提供技能完成，不能证明宿主会正确自动选择或抑制该技能。
宿主发现、显式调用与人工入口的自动调用禁用，需要在相应宿主中单独核对。
未执行的部分保留为未验证，不从元数据正确推断全部运行行为。
