# 可复用的验证能力

用于建立或维护项目验证方法。围绕需要证明的行为，复用现有运行入口、测试、
控制工具和数据准备方式；缺少关键能力时补齐最小有用部分。

一次可用的方法要让执行者到达正确的实例和初始状态，通过真实使用入口施加
动作，观察结果及重要副作用，并收回自己创建的运行资源。启动成功或端口可达
未必表示目标功能已经可操作；版本、认证和数据前提需要与本次证明相符。

采用工具真实支持的操作，优先稳定的语义句柄、命令和公开接口。程序内部的
状态设置不能替代从用户入口验证；外部系统需要替身时，说明被隔离的边界和
尚未得到的真实连接证据。重复工作值得工具化时，保留别人能够复跑的入口。

Feature map 按用户能力组织。记录如何到达、必要前提、关键动作、可观察的
结果和已知陷阱；共同启动方式引用已有方法。保存提示可能不足以证明持久化，
需要选择能识别目标失败的观察。覆盖范围由目标和影响决定，不能用一个方便
入口的成功代表所有受影响路径。

新写的驱动方法需要实际运行才能证明可用。未运行或受阻的部分明确留下，
不填造命令、结果或截图。只有行为符合预期但方法失效时才修正地图或驱动；
产品回归应被识别，不能通过删去失败场景掩盖。

证据保留对象、版本、条件、操作和结果之间的联系，读者能够判断它证明什么。
后续代码或环境变化时，重验受到影响的部分；不要无条件沿用，也不无依据
推翻全部已有证据。

隔离和清理以资源归属为准。只清理本次创建且已无用途的资源，不影响使用者
的工作实例或数据。证据保存在清理范围之外，并在交付时仍能找到。
